# Программа "Старший по обедам" (Ambassador Program) - Техническая документация

## Обзор
Система для работы с самоорганизованными командами:
- **Ambassador** (Старший) - организатор, получает бесплатный обед при достижении минимума
- **TeamMember** (Участник команды) - сотрудники, оплачивающие обеды онлайн через ЮКасса

## Этапы реализации

### Этап 1: Airtable (выполнен пользователем)
См. `AMBASSADOR_AIRTABLE_SETUP.md`

### Этап 2: Backend API (✅ Готово)

#### Новые endpoints:
1. **`GET /api/pricing_plan`** - получение тарифов и параметров программы
   - Параметры: `org`
   - Возвращает: цены (Full/Light), минимумы, адрес доставки, банковские реквизиты

2. **`GET /api/ambassador/team_stats`** - статистика команды на дату
   - Параметры: `org`, `date`
   - Возвращает: количество заказов, статусы минимумов, список участников

3. **`POST /api/ambassador/apply`** - заявка на участие в программе
   - Принимает: ФИО, телефон, email, размер команды, адрес
   - Создает запись в `AmbassadorApplications`

4. **`GET /api/test_ambassador_setup`** - проверка настройки Airtable

#### Модифицированные handlers:
- **`employee_info.js`** - теперь возвращает `role`
- **`order.js`** - логика для Ambassador/TeamMember:
  - **TeamMember**: Meal Box с `Line Type = 'Pending'` (требует оплаты)
  - **Ambassador**: Meal Box с `Line Type = 'Included'` (бесплатно)
  - Extras для TeamMember идут через paidExtras, не через included.extras

### Этап 3: Frontend - OrderClient (✅ Готово)

#### Изменения в `src/app/order/OrderClient.tsx`:
1. **Блок с ценами** (вверху страницы):
   - Показывается только для `contractType = 'Ambassador'`
   - Отображает цены на "Полный" (салат+суп+основное+гарнир) и "Лёгкий" (суп+основное+гарнир) обеды
   - Условия доставки (минимумы, адрес)

2. **Счетчик заказов** на кнопках дат:
   - Показывается для Ambassador/TeamMember
   - Формат: `paid_orders / min_for_delivery`
   - Цвет: зелёный (достигнут минимум) / жёлтый (не достигнут)

3. **Футер с реквизитами** (внизу страницы):
   - Показывается только для `contractType = 'Ambassador'`
   - Отображает юридическое название, ИНН, КПП, телефон, дополнительную информацию

4. **Кнопка "Личный кабинет Амбассадора"**:
   - Показывается в панели "Информация о сотруднике" только для роли `Ambassador`

#### Новые API routes:
- `src/app/api/pricing_plan/route.ts` - proxy для `/api/pricing_plan`
- `src/app/api/ambassador/team_stats/route.ts` - proxy для `/api/ambassador/team_stats`

#### Конфигурация:
- `next.config.js` - добавлены `/api/pricing_plan` и `/api/ambassador` в `LOCAL_API_PREFIXES`

### Этап 4: Frontend - QuizClient для TeamMember (✅ Готово)

#### Изменения в `src/app/order/quiz/QuizClient.tsx`:

1. **Step 1 для TeamMember**:
   - Вместо кнопки "Далее" - два варианта обеда:
     - **"Полный обед"** - с ценой, описанием (салат+суп+основное+гарнир)
     - **"Лёгкий обед"** - с ценой, описанием (суп+основное+гарнир)
   - При выборе "Лёгкий" - пропуск Step 2 (салат)

2. **ConfirmStep для TeamMember**:
   - Отображение стоимости выбранного обеда (синий блок)
   - Отдельный блок для платных дополнительных блюд (если есть)
   - **"Итого к оплате"** - сумма обеда + допы
   - Кнопка: "Оплатить и подтвердить"

3. **submitOrder для TeamMember**:
   - Рассчитывает `totalPayable = mealCost + paidExtrasTotal`
   - Инициирует оплату через ЮКасса для любой суммы > 0
   - Описание платежа: `"Обед (350₽) + Доп. блюда (280₽)"` или просто `"Обед Полный/Лёгкий"`

### Этап 5: Ambassador Dashboard (✅ Готово)

#### Новая страница: `src/app/ambassador/page.tsx`

**Функциональность:**
1. **Проверка доступа** - только для роли `Ambassador`
2. **Выбор даты** - календарь с доступными датами
3. **Статистика команды**:
   - Прогресс-бары для двух минимумов (доставка, бесплатный обед)
   - Визуальные индикаторы статусов (зелёный/жёлтый)
4. **Список участников**:
   - ФИО, роль (Амбассадор/Участник)
   - Статус заказа (✓ Заказал / —)
   - Статус оплаты (Оплачено/Ожидает оплаты)
5. **Уведомления**:
   - ⚠️ Минимум для доставки не набран (сколько заказов осталось)
   - ℹ️ Обед будет платным (если не набран минимум для бесплатного обеда)

**Доступ:** `/ambassador?org={org}&employeeID={id}&token={token}`

## Тестирование

### Сценарий 1: TeamMember заказывает Полный обед без допов
1. Открыть `/order` с кредами TeamMember
2. На главной странице видеть:
   - Блок с ценами (350₽ / 280₽)
   - Условия доставки
   - Счетчик заказов на датах
   - Футер с реквизитами
3. Выбрать дату → Quiz → Step 1:
   - Показываются два варианта обеда (не кнопка "Далее")
4. Выбрать "Полный обед" → Step 2 (салат) → ... → ConfirmStep:
   - Отображается стоимость обеда: 350₽
   - Кнопка: "Оплатить и подтвердить"
5. Нажать кнопку → редирект на ЮКасса
6. Оплатить → возврат на `/payment/result` со статусом "succeeded"
7. В Airtable:
   - `Meal Box.Line Type = 'Paid'`
   - `Order.Employee Payable Total = 350`

### Сценарий 2: TeamMember заказывает Лёгкий обед + допы
1. На Step 1 выбрать "Лёгкий обед" (280₽)
2. Пропуск Step 2 (салат), сразу на Step 3 (суп)
3. На ConfirmStep:
   - Стоимость обеда: 280₽
   - Добавить допы (например, +150₽)
   - Итого: 430₽
4. Оплатить → проверить в Airtable суммы

### Сценарий 3: Ambassador заказывает обед
1. Открыть `/order` с кредами Ambassador
2. Видеть кнопку "👑 Личный кабинет Амбассадора"
3. Сделать заказ (обычный flow, без оплаты)
4. В Airtable: `Meal Box.Line Type = 'Included'`

### Сценарий 4: Ambassador Dashboard
1. Открыть `/ambassador?org=...&employeeID=...&token=...`
2. Выбрать дату
3. Проверить статистику:
   - Прогресс-бары для минимумов
   - Список участников с их статусами
   - Уведомления (если минимум не набран)

### Сценарий 5: Счетчик на датах
1. Открыть `/order` как TeamMember или Ambassador
2. На кнопках дат видеть счетчик `X / Y`:
   - X - количество оплаченных заказов
   - Y - минимум для доставки
   - Зелёный (если достигнут) / Жёлтый (если нет)

## Архитектурные решения

### Почему каждая команда - это `Organization`?
- Упрощает переиспользование существующей логики (cutoff, dates, menu, pricing)
- Каждая команда может иметь свой адрес доставки и тарифный план
- Возможность масштабирования (несколько команд на один адрес)

### Почему `Line Type = 'Pending'` для TeamMember?
- Единая логика с существующей функцией платных допов
- Автоматический переход в 'Paid' при успешной оплате (через `payment_webhook` / `payment_status`)
- Фильтрация в отчетах (кухня видит только 'Included' и 'Paid')

### Почему `Line Type = 'Included'` для Ambassador?
- Упрощает начальную логику (Ambassador получает обед бесплатно по умолчанию)
- В будущем cron job может переводить в 'Pending' если минимум не набран

### Почему `PricingPlans` как отдельная таблица?
- Возможность назначать один тарифный план нескольким командам
- Централизованное управление ценами
- История изменений цен (через Airtable audit)
